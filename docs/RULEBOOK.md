# RULEBOOK.md

## Purpose & Scope

This document serves as the operational rulebook and troubleshooting reference for developing, testing, and running benchmarks in this repository. It documents the critical platform-specific quirks, environment traps, and runtime behaviors encountered on Windows with the Kaggle CLI and `kaggle-benchmarks` Python SDK, along with their mandatory solutions.

---

## 1. Authentication & Token Encoding (Avoid UTF-8 BOM)

### The Problem
When creating the access token file `~/.kaggle/access_token` in PowerShell using standard output redirection (`>`) or `Set-Content -Encoding utf8`, Windows PowerShell 5.1 writes a UTF-8 Byte Order Mark (BOM: `0xEF, 0xBB, 0xBF`) to the beginning of the file.

Because the Kaggle CLI treats the token file as raw text without stripping the BOM, authentication fails silently or reports:
```text
Authentication required to call the Kaggle API.
```

### Mandatory Rules
1. **Never write `access_token` using default PowerShell redirection or `Set-Content -Encoding utf8`**.
2. Write raw ASCII / clean UTF-8 without BOM:
   ```powershell
   [System.IO.File]::WriteAllText("$HOME\.kaggle\access_token", "YOUR_TOKEN_HERE")
   ```
3. Set the User environment variable as a fallback:
   ```powershell
   [Environment]::SetEnvironmentVariable("KAGGLE_API_TOKEN", "YOUR_TOKEN_HERE", "User")
   ```
4. Verify token bytes using `Format-Hex "$HOME\.kaggle\access_token"` (must start with `4B 47 41 54` (`KGAT`), NOT `EF BB BF`).

## 2. Multi-Drive & Site-Packages `.env` Loading

### The Problem
In cross-drive setups (e.g., project repository on `D:\work\Kaggle-challenge` while Python and its `site-packages` reside on `C:\Users\...\AppData\Local\Programs\Python`), `kaggle_benchmarks._config` calls `dotenv.find_dotenv()` during package import.

Because `find_dotenv()` defaults to inspecting the caller's stack frame without `usecwd=True`, it resolves to `kaggle_benchmarks` inside `C:\...site-packages`, walking up the directory tree of `C:\` and **never** finding `.env` on `D:\`.

This results in:
```text
ValueError: Missing environment variables for Kaggle authentication:
  - MODEL_PROXY_URL
  - MODEL_PROXY_API_KEY
```
even though `.env` exists in the repository root and was properly generated by `kaggle b init -y`.

### Mandatory Rules
Every benchmark task script MUST load `.env` explicitly before importing `kaggle_benchmarks`:

```python
# %%
from dotenv import find_dotenv, load_dotenv

load_dotenv(find_dotenv())

import kaggle_benchmarks as kbench
```

> [!IMPORTANT]
> Do not import `kaggle_benchmarks` before invoking `load_dotenv(find_dotenv())`. On import, `kaggle_benchmarks` binds `kbench.llm` to `_NotConfiguredLLM` if credentials are not yet present in `os.environ`.

## 3. Windows Terminal Character Encoding (`PYTHONUTF8=1`)

### The Problem
The standard Windows console / PowerShell terminal often defaults to legacy codepages (such as `cp1252`).

When `kaggle_benchmarks` finishes executing a task or logs events, `kaggle_benchmarks.ui.console` prints Unicode symbols and emojis (e.g., `✅` `\u2705` for passing assertions, or `🤖` `\U0001f916` for model names). On default Windows terminals, this raises:
```text
UnicodeEncodeError: 'charmap' codec can't encode character '\u2705' in position ...: character maps to <undefined>
```
This causes Python to exit with code 1, crashing an otherwise completely successful test run after the LLM call and assertions have already passed.

### Mandatory Rules
1. Set `PYTHONUTF8=1` in the Windows User environment permanently:
   ```powershell
   [Environment]::SetEnvironmentVariable("PYTHONUTF8", "1", "User")
   ```
2. When launching standalone commands or scripts in subshells, always ensure UTF-8 is active:
   ```powershell
   $env:PYTHONUTF8 = "1"
   ```

## 4. Task Structure & The Silent No-Op Gotcha

### The Problem
The Kaggle CLI checks for `@kbench.task(...)` decorators when pushing a file, but **does not verify whether the task is actually invoked**.

If a task file defines a task function but omits the `.run()` invocation at the bottom:
- Pushing the task (`kaggle b t push`) succeeds without warnings.
- Server-side execution executes the file as a script.
- Because `.run()` is never called, no `.run.json` artifact is produced, and nothing is recorded or scored on Kaggle.

### Mandatory Rules
1. **Mandatory `.run()` invocation**: Every task file must terminate with an explicit `.run()` call:
   ```python
   my_task.run(kbench.llm)
   ```
2. **Jupytext Percent Cell Formatting**: Always include `# %%` cell markers for cell boundaries.
3. **Canonical Model Slugs**: Always use bare canonical model slugs (e.g., `gemini-3.5-flash`, `claude-haiku-4-5-20251001`). Do not prepend provider prefixes like `google/` or `anthropic/`.
4. **Local Validation Before Push**: Always test tasks locally first with `python task.py` and confirm that a `*.run.json` output file is generated before calling `kaggle b t push`.

## 5. Dataset Attachment Persistence

### The Problem
If a prior version of a benchmark task had Kaggle datasets attached via `-d / --kaggle-dataset`, pushing an update with `kaggle b t push` without repeating all `-d` flags will **silently detach** the datasets on the server.

### Mandatory Rules
- Always maintain and re-pass the complete list of attached datasets on every push:
  ```powershell
  kaggle b t push <TASK_NAME> -f <TASK_FILE> -d owner/dataset1 -d owner/dataset2 --wait
  ```
- Repeat the `-d` flag once per dataset (never use space-separated values for multiple datasets).

## 6. Workspace Hygiene & Ignored Files

### The Problem
Running benchmark tasks generates short-lived execution credentials (`.env`), run output dumps (`*.run.json`), task definitions (`*.task.json`), and Python caches (`__pycache__`). If committed to Git, credentials may leak and repository history will bloat.

### Mandatory Rules
Ensure `.gitignore` contains at least:
```gitignore
*bad-work/
*.agents/
.env
*.run.json
*.task.json
__pycache__/
```

## 7. Workflow Pacing Checklist

Follow this linear sequence for every benchmark task:

```text
[Step 0: Init / Auth]     --> kaggle b init -y (or kaggle b auth -y to refresh credentials)
[Step 1: Write Task]      --> Create task file with explicit dotenv loading and .run()
[Step 2: Validate Local]  --> python task.py (verify code 0 and *.run.json creation)
[Step 3: Push Task]       --> kaggle b t push <SLUG> -f <FILE> --wait
[Step 4: Run Task]        --> kaggle b t run <SLUG> -m <MODEL_SLUG> --wait
[Step 5: Check Status]    --> kaggle b t status <SLUG>
[Step 6: Download]        --> kaggle b t download <SLUG> -o ./results -s
```
